# 0009: UX P1 trio (preparing state, human errors, first-jump hint)

Status: built (275 tests; live checks 23-25 in the final hands-off run)
Date: 2026-07-12
Depends on: 0001-0008. The three pre-launch fixes from the first-principles
UX review (mycroft outputs/speaking-editor-ux-review-2026-07-12.html):
close the loop's edges: start, failure, and learning.

## 1. The preparing state (feedback: every action answers immediately)

Between pressing play and the first audio there are two to four silent
seconds of synthesis. Surface them:

- New session state "preparing": a session enters it the moment playback
  is requested (start, resume with an unloaded chunk, or seek to an
  unloaded chunk) and leaves it when audio actually starts (engine emits
  "playing") or fails. Detection lives in the shell session (the vendored
  engine stays untouched): requested-but-not-yet-playing is knowable from
  the session's own calls plus the engine state callbacks.
- The pill's play button shows a quiet pulse while preparing (CSS
  animation on opacity only, no motion), and keeps the pause glyph since
  a press during preparing should pause/cancel.
- The ribbon icon mirrors it (icon swaps to a loader glyph, lucide
  "loader-2" with the pulse class).
- A press during "preparing" pauses (cancels the pending start), exactly
  like pressing pause: no dead controls during the gap.

## 2. Human error copy with a one-tap way out (an error is a fork)

Today a mid-session failure surfaces the raw exception text in a Notice.
Replace with:

- Error taxonomy in the shell: network-ish failures of the active
  provider map to a plain sentence naming the provider, not the
  exception ("The free Edge voice could not be reached.").
- The error Notice (persistent until dismissed, timeout 0) carries one
  action: on macOS with a non-say provider active, a button "Switch to
  the offline voice" that calls the existing applyProvider("say") and
  restarts reading from the current position (the reconfigure path);
  elsewhere, a button "Open settings" via the existing openSettingsTab.
  Notices accept DOM children; build the button into the notice element.
- The raw error string still goes to console.error for debuggability,
  never to the user.

## 3. The first-jump teaching hint (a mode is only as good as awareness)

The first N (3) times a click actually seeks playback, show a transient
hint anchored near the pill: "Jumped here. That is listening mode; the
ear turns it off." Small, dismisses itself after 4 seconds, never blocks
input, opacity-only transitions.

- Counter `seekHintsShown` persisted in settings (data.json); stops
  forever at 3. Resetting is deliberately not surfaced (docs can mention
  deleting the setting).
- The hint element lives with the pill module (same styling family,
  class prefix se-hint), created by main.ts's seek path when the counter
  allows; a hint that is already visible is not re-created.

## Out of scope

Remaining-time label, ending fade, edited badge, chunk-0 warm-up (P2s,
next spec), any engine/vendored changes.

## Test-first requirements

- Session preparing-state transitions as a pure state table where
  feasible (request -> preparing; engine playing -> playing; engine
  paused while preparing stays preparing only for prime-paused flows;
  error -> error; pause during preparing -> paused): unit-test the
  session's state exposure with a fake engine/audio like the vendored
  suite does.
- Error mapping: provider + error -> user sentence + action kind
  (offline-fallback vs open-settings), pure and unit-tested, including
  the say-not-available-off-macOS branch.
- Hint gating: pure counter logic (shows at 0,1,2; never at 3+),
  unit-tested.

## Acceptance (in-app checks appended)

23. Immediately after play on an uncached note, the session reports
    "preparing" and the pill root carries the preparing class; when
    "playing" arrives both clear.
24. With a provider stub that rejects (inject via the harness session),
    the user-visible Notice text contains the provider's plain-language
    sentence and an action button exists; the raw exception string does
    NOT appear in the notice.
25. With seekHintsShown reset to 0, a synthetic seek click shows the
    hint element; setting the counter to 3 and seeking again shows none.

Manual (Rishabh): press play on a long uncached note and watch the pill
breathe until the voice starts; pull the network and press play (error
notice reads like a product, one tap lands on the offline voice); click
around on first use and see the hint teach listening mode, then stop
appearing.

## Constraints

No em dashes. No vendored-file changes. Opacity-only animation. Notice
copy in plain language, no stack traces. All three features must be
inert during acceptanceRunning where they would interfere (the hint
during harness seeks is acceptable; the checks account for it).
