# 0011: UX P3 trio (ear label, hotkey guidance, first-play tip)

Status: built (312 tests; live check 30 in the next hands-off run)
Date: 2026-07-12
Depends on: 0009, 0010. The radar tier from the UX review, promoted to
build-now on Rishabh's call (2026-07-12). Small, self-contained, no new
mechanisms.

## 1. The ear gets its word

The pill's listening-mode ear control gains a small text label
("listening") to its right, part of the same button: dim when the mode
is off, accent-colored when on, so the mode is readable at a glance
without hovering. setListening drives both.

## 2. Hotkey guidance where users will see it

README quick start gains a power-use step: assign a hotkey to "Play or
pause reading" (Settings -> Hotkeys, search "Speaking Editor"), with the
note that the plugin deliberately ships no default hotkey (Obsidian
convention: defaults collide with user muscle memory). No code change.

## 3. The first-play tip

On the first play EVER (flag `firstPlayTipShown` in settings, default
false), a single Notice: "Tip: click any word to jump the reading
there." Shows once, then never again. It complements the 0009 hint: the
tip teaches before the first click, the hint confirms after a real one.
The harness's settings snapshot/restore covers the flag (added to the
restore list), so verification runs never burn it for real use.

## Tests

Pill: setListening(on/off) reflects on the label element's classes and
the label text exists (extend the existing happy-dom suite). Settings:
firstPlayTipShown default false + merge coverage. Tip gating is a
one-line branch exercised through the settings default test plus the
acceptance check.
