# 0010: UX P2 quartet (time left, graceful endings, edited badge, warm start)

Status: building
Date: 2026-07-12
Depends on: 0009. The first-point-release tier from the UX review
(mycroft outputs/speaking-editor-ux-review-2026-07-12.html): visible
progress, closure, honest degradation, perceived speed.

## 1. Remaining time in the pill (visible status)

- A dim label in the pill ("~12 min left") between the voice label and
  the ear. Estimation: mean ms-per-word from every loaded chunk's
  timings, divided by the current speed, times words remaining after the
  current word. Pure function `remainingLabel(msPerWord, wordsLeft,
  speed)` with rounding rules: >= 90s rounds to minutes ("~12 min
  left"), 20s to 90s says "~1 min left", under 20s says "almost done";
  unknown (no timings yet) renders empty.
- Updates on sentence change (not every word; calm), and on speed change.
- Estimation source lives in the session (it owns timings): expose
  `remainingEstimate()` returning { msPerWord, wordsLeft } or null.

## 2. Graceful endings (closure)

- Natural end: the final word's highlight lingers 600ms before the
  surface clears, and the pill fades out (se-pill-leaving class, 200ms
  opacity transition) before removal. Manual stop keeps the immediate
  clear for decorations (the user asked for silence NOW) but the pill
  still fades out instead of popping.
- Implementation: session delays surface.clear() by 600ms on the
  "ended" path only (cancelable if a new request arrives); main.ts adds
  the leaving class and removes the pill on transitionend with a 300ms
  timer fallback. Dispose during the linger cancels cleanly.

## 3. The edited badge (say what degrading means)

- When a session's dirty word count crosses 3, the pill shows a dim
  "edited" text badge whose title attribute explains: "The note changed
  while reading; the voice is finishing the text it started. Stop and
  play again to re-read." Disappears if a fresh session starts; count is
  per session.
- Dirty count comes from the sync field (live preview); the reading-mode
  surface has no live edits (rendered view), so the badge is a
  live-preview behavior only.
- Pill API: setEdited(on).

## 4. Warm start for the free voice (perceived speed)

- When the active note changes (file-open/active-leaf-change), IF all
  guardrails pass, quietly synthesize chunk 0 of that note into the disk
  cache so a later play starts near-instantly. Guardrails, all required:
  the plugin has already played at least once this app session; the
  active provider is Edge (keyless; never spend paid credits
  speculatively); no session is active; the chunk-0 cache key is a miss;
  at most one warm-up in flight (a new note switch aborts the previous
  via AbortController).
- Uses the SAME cache instance and key scheme as sessions, so the warmed
  chunk is exactly what play would request. No audio element, no UI, no
  Notice: purely a cache write. Failures are silently ignored (warm-up
  is opportunistic).
- Pure gate `shouldWarmUp(state)` unit-tested (each guardrail flips it).

## Out of scope

Scrubber, per-note speed, P3 items (ear label, default hotkey, first-
play tip), cache statistics.

## Test-first requirements

- remainingLabel rounding table (empty, almost done, ~1 min, minutes).
- Session remainingEstimate with fake timings (mean across chunks,
  speed division, wordsLeft arithmetic).
- shouldWarmUp guardrail matrix.
- Pill setEdited and leaving-class behavior (happy-dom).
- Ending linger: session fake-engine test that "ended" delays clear
  600ms and a new play cancels the linger.

## Acceptance (in-app checks appended)

26. During playback the pill shows a remaining-time label once timings
    exist, and it shrinks as reading proceeds (sample twice 3s apart).
27. Natural end (use a two-sentence tiny fixture): the last word's
    highlight is still present 300ms after "ended", gone by 1200ms, and
    the pill element leaves the DOM after its fade.
28. Three edits inside words during playback flip the edited badge on;
    a fresh session starts without it.
29. With the guardrails satisfied (played once, Edge, idle, cache miss),
    switching to a never-played note writes chunk-0 cache files within
    10s without creating a session or audio; switching with a session
    ACTIVE does not warm up.

Manual (Rishabh): watch the minutes count down and drop when you bump
speed; let a short note finish and feel the ending breathe instead of
snap; type over a paragraph mid-listen and see the quiet "edited" badge;
open a fresh long note, wait a beat, press play and notice it starts
almost instantly.

## Constraints

No em dashes. No vendored-file changes (the warm-up composes
SynthesisService + DiskCache from outside). Opacity-only transitions.
The warm-up must be invisible: no UI, no sound, no state changes beyond
the cache write.
